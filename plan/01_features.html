功能清单

7 个模块，每个附 before / after 实例。

F1JSON Formatter

把任意 JSON 字符串格式化为可读 / 可压缩形式。选项：缩进（2 / 4 空格 / Tab）、Sort keys、Minify。

Input
{"name":"alice","age":30,"items":["a","b"],"meta":{"created":"2026-05-22"}}
→
Output
{
  "name": "alice",
  "age": 30,
  "items": ["a", "b"],
  "meta": {
    "created": "2026-05-22"
  }
}

错误处理：实时高亮非法位置（行号 + col）；错误时显示「AI Fix」入口（前提 AI 已启用）。

编辑器交互（左侧 input panel · CodeMirror 6 内置；同样适用于 F3 / F4 等所有 input 区）：

  • Soft-wrap 软换行：长行自动换行，不出现水平滚动条（默认开，设置可关）
  • 括号匹配高亮：光标停在 { / [ 时，对应 } / ] 高亮蓝框（CodeMirror bracketMatching extension）
  • 缩进引导垂直线：每层缩进一条浅色 vertical guide line，方便定位嵌套层级（类似 VSCode indent guides；indentationMarkers extension）
  • 大数组 / 大对象折叠：超过阈值的 array / object 自动折叠为 [ … ] / { … }，点击展开 / 收起（CodeMirror foldGutter + codeFolding）
  • 行号 / 当前行高亮 / ⌘F 搜索 / ⌘D 多光标 / ⌘Z undo：CodeMirror 6 内置

F2JSON TreeView

JSON 解析后渲染成可折叠树状视图，方便浏览嵌套结构与复制 JSON Path。

Input
{
  "user": {
    "name": "alice",
    "active": true,
    "age": 30
  },
  "items": ["a", "b", "c"],
  "extra": null
}
→
Tree view
▾ root{3}
▾ user{3}
name: "alice"
active: true
age: 30
▾ items[3]
[0]: "a"
[1]: "b"
[2]: "c"
extra: null
  • 点击 key → 复制 JSON Path（如 user.name / items[1]）
  • 折叠 / 展开任意子树；搜索高亮 key & value
  • 大对象（> 50 keys）默认折叠到第 2 层
  • 类型颜色："string" · 42 · true/false · null

Hover 复制节点（v1）：

  • 鼠标悬停任意 node → 右侧浮出 📋 小图标（仅 hover 出现）；点击复制并 toast 反馈
  • leaf 节点（string / number / bool / null）→ 复制该 raw value，带原始引号或字面量："alice" / 30 / true / null
  • object / array 节点（含 root）→ 递归复制完整子树为 pretty-printed JSON（2 空格缩进），即"以该 node 为新 root 的合法 JSON"
  • 与点 key 复制 path 不冲突：点 key 仍复制 path；hover 出现的 📋 与 key 点击行为分开
  • 键盘可达：聚焦在某个 node 行时按 ⌘C 等同于点 📋

F3JSON ↔ String 互转

常用于日志反解析、把 JSON 拷贝进代码字符串字面量等。

F3.1String → JSON（反解转义）

Input · escaped string
"{\"user\":{\"name\":\"alice\",\"age\":30}}"
→
Output · valid JSON
{
  "user": {
    "name": "alice",
    "age": 30
  }
}

F3.2JSON → String（转义打包）

Input · JSON
{
  "msg": "hi\nworld",
  "ok": true
}
→
Output · string literal
"{\"msg\":\"hi\\nworld\",\"ok\":true}"

选项：单 / 双引号包裹切换；高亮 \n \t 等可视；支持 4 层嵌套转义。

F3.3嵌套 Stringified JSON 全量解开

常见于 Golang proto 序列化场景：JSON 字段值本身又是 stringified JSON。一键递归展开为纯 JSON。

Input · proto 风格嵌套
{
  "code": 200,
  "data": "{\"name\":\"alice\",\"age\":30}",
  "extra": "{\"tags\":[\"a\",\"b\"]}"
}
→
Output · 全量解开
{
  "code": 200,
  "data": {
    "name": "alice",
    "age": 30
  },
  "extra": {
    "tags": ["a", "b"]
  }
}
  • 策略：检测字符串字段能否 JSON.parse 成对象 / 数组 → 是则递归展开
  • 无层数限制：递归到底；用超时而非"拍一个层数"来防失控
  • 超时失败：单次解析超过阈值（默认 200 ms，可调）即停，避免死循环 / 巨型嵌套卡 UI
  • 开关：可在设置中关闭（Format / Tree 默认启用）

F4AI Auto Fix（DeepSeek）

JSON parse 失败时一键调 DeepSeek 修复。按钮仅在解析失败时显示，无误触。

Input · 非法（多 comma + 单引号 + 无引号 key）
{
  name: 'alice',
  age: 30,
  items: ["a", "b",],
}
AI
Output · DeepSeek 修复
{
  "name": "alice",
  "age": 30,
  "items": ["a", "b"]
}
  • Prompt 策略：严格要求「只返回合法 JSON，无解释 / markdown 包裹」
  • 验证：本地 try-parse 验证返回；失败给出原始返回供调试
  • 呈现：diff 形式展示修复点，用户决定接受 / 撤销
  • 开关：可在设置完全关闭，关闭后入口全部隐藏，代码层面零网调
  • 不做客户端节流：用户用自己的 API key，是否「省 token」是用户决定；仅透传上游 429（含 retry-after）

F8会话保留与恢复

关闭浮窗后短期内再呼出，自动恢复上次内容；超时视为新会话；任何时刻 ⌘⇧L 可手动找回。

场景行为
关闭后 5 min 内呼出（默认窗口期）自动恢复内容 + 顶部提示「Restored from N min ago · Discard」
超过 5 min 呼出视为新会话，输入框空白；需手动按 ⌘⇧L 找回
应用 Quit 重启同上：默认空白；按 ⌘⇧L 仍可找回（sqlite 持久化）
按 ⌘⇧L（任意时刻）从 sqlite last_session 读取并载入
按 ⌘K 主动清空立即清空 + 不写入「上次会话」（避免找回的是空）

实现要点：

  • 关闭时把当前内容写入 sqlite last_session 单行表（覆盖式）+ 同时写入普通 history 表
  • 恢复窗口期由 in-memory 计时器维护，不持久化 —— 应用 Quit 后计时器销毁，下次启动默认不自动恢复
  • ⌘⇧L 始终从 last_session 读取，与内存计时器无关
  • 恢复提示 bar 显示在浮窗顶部，5 秒后自动淡出（或用户点 Discard 立即清空内容）

设置项（General 分组）：Restore session within — Off / 1 min / 5 min（默认）/ 15 min / 1 hour

F9单窗模式 (Single-pane Mode)

可选模式：默认是左右双栏（input | output）对比；开启后取消右侧 output 面板，操作（Format / Minify / 互转 / AI Fix）直接 in-place 替换 input 内容；按 ⌘Z 回滚到上一步。

  • 适用场景：屏幕小、喜欢极简、习惯 sed / jq 风格的 in-place 编辑
  • 开关：F7.1 General「☐ 单窗模式」（默认关）
  • 回滚：CodeMirror 6 内置 history extension 提供 undo 栈，原生 ⌘Z / ⌘⇧Z
  • 回滚深度：跟随 CodeMirror 默认（约 100 步），不另设上限
  • 历史：每次操作仍写入 sqlite history（不依赖 undo 栈，重启后仍可找回）
  • AI Fix：单窗模式下不再 diff 双栏对比，改为 toast「已修复，⌘Z 撤销」

F10浮窗智能宽度

4 层独立逻辑，共同决定浮窗在任意时刻的宽度。原则：克制，最大不占满屏；初次打开也不能太小。

层触发行为用户可控？
1. 首次呼出宽度 新光标屏第一次呼出 / 用户从未拖动过 固定 920 px（在 720-1400 区间偏中）；高度按光标屏可用区域 ≈ 65% 设置 General「初始宽度」可改预设档（720 / 860 / 920 / 1080）
2. 粘贴自动扩宽 粘贴或编辑器内容首次填充 → 行长 / 字符数 / 缩进结构 评估"理想宽度" = min(max_line_length × char_width + padding, 屏幕宽 × 70%)；动画过渡到该宽度（150 ms） 设置 General「智能扩宽」总开关；soft-wrap 开时本层跳过（不需要扩宽）
3. 手动拖动 用户从窗口边缘拖动 resize 立即覆盖上述自动逻辑；记忆到 window.json；下次呼出沿用 始终可拖；不可关闭
4. soft-wrap 编辑器内长行 开 → 长行换行不溢出，配合层 1-3；关 → 编辑器内水平滚动，浮窗本身不变宽 设置 F1 编辑器「Soft Wrap」（默认开，已在 F1 中）

克制原则的具体数字：

  • min 宽度：720 px（不能小于 plan/02 锁定的 minWidth）
  • max 宽度：min(1400 px, 当前屏宽 × 70%) ── 13 寸屏 ≈ 1440 × 0.7 = 1008 px；27 寸屏 ≈ 2560 × 0.7 = 1792 px 但被 1400 上限封顶
  • min 高度：480 px（同上）
  • max 高度：屏高 × 75% ── 防止占满
  • "够长就扩" 阈值：max line length > 80 ch 才触发层 2；否则保持当前宽

层 2 与层 3 的关系：

  • 用户从未拖动 → 每次粘贴都重新评估理想宽度（层 2 主导）
  • 用户一旦拖动 → 用户尺寸"粘住"，不再因粘贴自动变（层 3 锁定）
  • 重置：设置 General「重置浮窗尺寸」按钮，清掉 window.json → 回到层 1+2 行为

非常用场景：

  • 多屏切换：屏宽变化时按新屏重新评估 max；不缩小用户拖动的尺寸（除非已超新屏 max）
  • 用户把浮窗拖出 max 限制（如设 1600 px）：允许；记忆原样
  • 极大 JSON（> 100 KB）：不评估理想宽度，沿用上次大小 + soft-wrap 兜底
