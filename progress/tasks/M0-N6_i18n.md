# M0-N6 · i18n 框架（react-i18next）

## Goal

接入 `i18next` + `react-i18next`；建 7 个 namespace 骨架（shell / panes / settings / history / errors / about / common）；M0 阶段只填 `en-US` 一份（zh-CN 解锁留 M3-N2）。所有 M0 / M1 / M2 阶段新增 UI 文案**强制**走 `useTranslation`，不允许 hardcode 英文字符串。

## Write Scope

- `package.json`（加 `i18next` · `react-i18next` · `i18next-browser-languagedetector`）
- `src/i18n/index.ts`（i18n 初始化 ── resources 全部 lazy import 各 namespace）
- `src/i18n/types.ts`（TypeScript 类型增强 ── 让 `t('key')` 有自动补全）
- `src/locales/en-US/shell.json`（"Open", "Close", "Settings", "Quit", "Toggle"...）
- `src/locales/en-US/panes.json`（"Paste JSON to start", "Tree", "Formatter"...）
- `src/locales/en-US/settings.json`（M0 阶段最小集合，M2 补全）
- `src/locales/en-US/history.json`（M0 最小集合）
- `src/locales/en-US/errors.json`（错误 kind 映射，M0 占位即可）
- `src/locales/en-US/about.json`
- `src/locales/en-US/common.json`（按钮 / 通用动词）
- `src/main.tsx`（`import './i18n'` + `i18n.init()` 在 React mount 前完成）

## Do Not Touch

- `src/locales/zh-CN/*.json` ── M3-N2 才解锁
- 字体 CJK 回退栈实际生效 → M3-N2（CSS `--font-mono` 末尾加 `"PingFang SC"`）
- Settings → Language Select 切换 UI → M2-N1 加 select；M3-N2 加 zh-CN 选项
- Rust 端错误翻译（spec/14 § 8 锁定：错误不翻译）── 本节点只在前端做 errors namespace 映射

## Verification

```bash
# 1. 类型检查
pnpm tsc --noEmit  # 应 0 错（包括 t() 的 key 自动补全）

# 2. 文件结构
ls src/locales/en-US/
# 应见 7 个文件: shell.json panes.json settings.json history.json errors.json about.json common.json

# 3. hardcode 英文扫描
grep -rE '"[A-Z][a-z]+ [A-Z][a-z]+"' src/ --include="*.tsx" --include="*.ts" \
  | grep -v "// "      # 排除注释
# 应该 0 命中（除框架/库引用的 className 等）

# 4. 运行
pnpm tauri dev
# - 浮窗中所有可见英文都从 JSON 来
# - DevTools console: i18n.languages 应见 ["en-US"]
# - document.documentElement.lang === "en-US"
```

## Stop And Ask / Update Spec When

- spec/14 § 5 的 7 个 namespace 边界在实施中发现需要重切（如 "panes" 太大） → 回改 spec/14
- 想加新 namespace（如 "diff"）→ 先 spec/14 加，再回本节点
- i18next v23 与某些 React 18 strict mode 不兼容 → 文档化 + 用 `react-i18next` 兼容版本

## Notes

- namespace 文件**懒加载**（不要一次性 import 全部）── 启动只加 shell + common，其他 on-demand
- 别人翻译时 zh-CN 文件命名严格对齐 en-US（路径 / key / 嵌套层级）── M3-N2 复制英文文件改值即可
- `t('errors.parse')` 失败时 fallback 到 key 本身（i18next 默认）── 但生产应该 0 fallback 命中（CI grep 锁）
- `useTranslation` 在 React strict mode double-mount 时 hook 调用顺序保持 ── 不要在条件分支内调
