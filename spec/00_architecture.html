SPEC · 章节 00

系统架构

进程模型、模块边界、数据流与错误传播。开发者从此处入手获得系统全貌。

1系统全景

Jsonita 是一个双进程桌面应用：Rust 主进程承载所有系统能力（菜单栏 / 快捷键 / SQLite / Keychain / HTTP），WebView 渲染进程承载 UI（React + CodeMirror）。两者通过 Tauri IPC 通信。

INFO

整套架构在 plan/03 技术选型 已锁定。本章只描述如何组合，不再讨论是否采用 Tauri / React / SQLite。

层承载组件关键库边界
表现层主浮窗 UI / 设置面板 / 历史列表 / Toast / 状态栏React 18, CodeMirror 6, Tailwind, shadcn/ui, react-json-view-liteWebView 进程内；不直接访问 fs / net / clipboard
逻辑层编辑器状态机、UI store、IPC 客户端Zustand, TypeScriptWebView 进程内；可调 Tauri command / 监听 event
IPC 层commands / events 合约Tauri 2 IPC, serde序列化通过 serde_json；payload < 1 MB 直接走 IPC，> 1 MB 走 chunked event
领域层JSON 引擎、AI Fix 调度、设置、会话恢复、历史serde_json, rusqlite, reqwest, keyring, tokioRust 主进程；纯函数优先
系统层菜单栏、全局快捷键、窗口、剪贴板、Accessibility 权限tauri-plugin-global-shortcut, tray-icon, tauri-plugin-clipboard-managerRust 主进程；macOS / Windows 抽象不同
持久化history.db / app_config.json / Keychain 条目rusqlite, tauri-plugin-store, keyring仅 Rust 端直接访问

2进程模型与生命周期

2.1进程拓扑

启动后常驻 1 个主进程（Tauri host），按需启动 1 个 WebView 进程（浮窗）。无 worker 子进程（v1）。

进程启动时机退出时机常驻内存目标
Rust host登录系统时（开机自启动）/ 用户首次启动用户在菜单栏点 Quit / ⌘Q≤ 40 MB（无浮窗时）
WebView 浮窗⌘⇧J / 点菜单栏图标失焦 / Esc / ⌘W（默认是 hide 不是 close，进程保留）≤ 80 MB（含编辑器空闲）
WARN

浮窗实际是常驻不销毁，关闭只是 window.hide() + 内存里保留 DOM。这换来 呼出 < 500ms 的首屏体验，代价是 ~80 MB 稳态内存 ── 与 04 NFR § 1 性能 锁定的目标一致。

目标 < 500 ms（P95）。预算分配：global-shortcut 20 ms · 窗口操作 80 ms · IPC 30 ms · React 渲染 50 ms · CodeMirror reflow 50 ms · 淡入 150 ms ≈ 380 ms 稳态。

6错误传播

6.1错误类型层级

Rust 端单一错误枚举 JsonitaError，所有内部错误统一映射；通过 serde 序列化跨 IPC 边界传到前端。

// src-tauri/src/error.rs
#[derive(Debug, thiserror::Error, serde::Serialize)]
#[serde(tag = "kind", content = "data")]
pub enum JsonitaError {
    #[error("JSON parse error at line {line}, col {col}: {msg}")]
    Parse { line: u32, col: u32, msg: String },

    #[error("Unwrap timeout after {ms}ms (depth reached {depth})")]
    UnwrapTimeout { ms: u64, depth: u32 },

    #[error("SQLite error: {0}")]
    Sqlite(String),

    #[error("Keychain error: {0}")]
    Keychain(String),

    #[error("HTTP {status}: {body}")]
    Http { status: u16, body: String },

    #[error("AI returned invalid JSON: {raw}")]
    AiInvalidJson { raw: String },

    #[error("Rate limited; retry after {retry_after_sec}s")]
    RateLimit { retry_after_sec: u64 },

    #[error("IO error: {0}")]
    Io(String),
}

6.2跨 IPC 传递

Tauri 自动把 Result<T, E> 的 Err 序列化为前端 invoke() 的 reject。前端类型：

// src/types/commands.ts
export type JsonitaError =
  | { kind: 'Parse';          data: { line: number; col: number; msg: string } }
  | { kind: 'UnwrapTimeout';  data: { ms: number; depth: number } }
  | { kind: 'Sqlite';         data: string }
  | { kind: 'Keychain';       data: string }
  | { kind: 'Http';           data: { status: number; body: string } }
  | { kind: 'AiInvalidJson';  data: { raw: string } }
  | { kind: 'RateLimit';      data: { retry_after_sec: number } }
  | { kind: 'Io';             data: string };
OK

设计原则：Rust 不对错误做"产品化"包装（不翻译成中文 / 不加 emoji）；UI 层根据 kind 决定如何展示给用户（Toast / 状态栏 / Modal）。

8关键不变量

  • I-1 单一数据源：浮窗内容只存在 React 编辑器 state；关闭时落 sqlite，重新呼出从 sqlite 读 ── 不在两处同步
  • I-2 设置项单源：所有可配置项以 Rust 端 tauri-plugin-store 为准；前端启动时 load + 监听变更
  • I-3 错误不藏：所有 IPC 错误必须有 UI 呈现（Toast / 状态栏 / Modal），不允许 silent fail
  • I-4 main 进程不阻塞：所有 IO（SQLite / HTTP / Keychain）走 tokio::spawn_blocking 或 async client
  • I-5 UI 不直访 fs/net：WebView 不开 fs / http allowlist；所有外部 IO 走 commands
  • I-6 AI 完全可关：settings.ai_enabled = false 时，前端 AI Fix Tab 隐藏 + Rust 端 ai_fix command 直接返回 kind: "Sqlite"-style error（早 return）── 双重保险
