一 · 设计

1系统全景

Jsonita 是一个双进程桌面应用：Rust 主进程承载所有系统能力（菜单栏 / 全局快捷键 / SQLite / 本地 secrets.json / HTTP），WebView 渲染进程承载 UI（React + CodeMirror）。两者通过 Tauri IPC pipe 通信，WebView 进程绝对不直接访问 fs / net / clipboard / secrets。

1.1六层职责

层位置承载边界硬约束
表现层WebView浮窗 UI / 设置面板 / 历史 / Toast / 状态栏不直访 fs / net / clipboard
逻辑层WebView编辑器状态机、UI store、IPC 客户端调 Tauri command / listen event；不持有持久数据

领域层RustJSON 引擎、AI 调度、设置、会话、历史纯函数优先；不持有 Tauri runtime context

2进程模型与内存预算

启动后常驻 1 个主进程（Tauri host）+ 1 个 WebView 进程（浮窗）。无 worker 子进程（v1）。

进程启动退出常驻目标
Rust host开机自启动 / 用户首次启动菜单栏 Quit / ⌘Q≤ 40 MB（无浮窗时）
WebView 浮窗⌘⇧J / tray 点击失焦 / Esc / ⌘W = hide 不 close；进程保留≤ 80 MB（含编辑器空闲）
WARN

浮窗常驻不销毁，关闭只是 window.hide()，DOM 保留在内存。这换来呼出 < 500 ms 的首屏体验，代价是 ~80 MB 稳态内存 ── 与 04 NFR § 1 锁定的目标对齐。

3关键不变量

下面 6 条是所有新代码必须遵守的硬规则。违反通常会导致状态不一致、数据丢失或安全风险。

不变量规则违反后果
I-1 单一数据源浮窗内容只存在 React 编辑器 state；关闭时落 sqlite；重呼出从 sqlite 读 ── 不在两处同步恢复后内容与用户输入不一致
I-2 设置项单源所有可配置项以 Rust 端 SettingsStore 为准；前端启动 load + 监听 settings:changed设置生效延迟 / 多窗口不同步
I-3 错误不藏所有 IPC 错误必须有 UI 呈现（Toast / 状态栏 / Modal），不允许 silent fail用户看不到为什么操作没反应
I-4 main 进程不阻塞所有 IO（SQLite / HTTP / secrets fs）走 tokio::spawn_blocking 或 async client菜单栏 / 快捷键 / 窗口卡顿
I-5 UI 不直访 fs/netWebView 不开 fs / http allowlist；所有外部 IO 走 commandsWebView 漏洞可读用户文件 / 偷 API key
I-6 AI 完全可关settings.ai_enabled = false 时 UI Tab 隐藏 + Rust early return ── 双重保险用户关了 AI 仍出网

二 · 工作机制

4启动时序（< 500 ms 就绪）

从 launchd 拉起到 WebView 待命的全过程。关键设计：浮窗在启动末尾就 hidden-built，呼出时只需 window.show()（亚毫秒）。

sequenceDiagram autonumber participant L as launchd participant R as Rust main participant DB as SQLite participant SYS as system 层 participant WV as WebView L->>R: 拉起 Jsonita.app（T+0） R->>R: tokio runtime · 初始化日志（T+~120ms） R->>DB: open(history.db) + migrate DB-->>R: ok R->>R: SettingsStore::load(settings.json) R->>SYS: tray::build · shortcuts::register_defaults SYS-->>R: ok R->>WV: WebViewWindowBuilder.build() (visible: false) WV-->>R: window created R->>SYS: promote_to_nspanel(win) (macOS) R->>WV: register_close_intercept(win) Note over R,WV: T+~500ms：WebView DOM 就绪，hidden 待呼出

预算分配：tokio 启动 ~120 ms · SQLite open + migrate ~60 ms · tray + shortcuts 注册 ~40 ms · WebView 预建 ~280 ms ≈ 500 ms。其中 WebView 预建占大头 ── 是为了 trade off 呼出延迟。

5呼出时序（< 500 ms P95）

sequenceDiagram autonumber actor U as 用户 participant GS as GlobalShortcut participant R as Rust host participant W as Tauri Window participant RC as React U->>GS: ⌘⇧J GS->>R: handler triggered (T+0) R->>R: cursor_position() → 找鼠标所在屏 (T+~10ms) R->>R: clipboard_sniff() · session.load_if_in_window() R->>W: set_position(光标屏中央偏上 1/3) R->>W: show() + set_focus() (T+~80ms) W-->>R: ok R->>RC: emit "window:shown" { clipboard, lastSession, source } RC->>RC: editor.focus() · 应用剪贴板 sniff · 显示 RestoreBar RC->>RC: CodeMirror reflow + 150 ms fade-in Note over U,RC: T+~380ms 总耗时（P95 < 500ms）

预算：shortcut handler 20 ms · 屏 + sniff + session 30 ms · window.show 80 ms · IPC + React 50 ms · CodeMirror reflow 50 ms · 淡入 150 ms ≈ 380 ms 稳态。

6典型数据流：format JSON

用户在编辑器粘贴 JSON → 自动格式化。展示 React store → IPC → Rust engine 的链路与 debounce 节流策略。

sequenceDiagram autonumber actor U as 用户 participant CM as CodeMirror participant ES as editor store participant IPC as ipc client participant CMD as cmds::json_ops participant ENG as engine::json U->>CM: 粘贴 / 输入 JSON CM->>ES: onChange(text) ES->>ES: debounce 300 ms · 合并连续 onChange ES->>IPC: invoke("json_format", { text, opts }) IPC->>CMD: json_format(text, opts) [async] CMD->>CMD: spawn_blocking (CPU 密集) CMD->>ENG: engine::json::format(text, opts) alt 成功 ENG-->>CMD: Ok(formatted) CMD-->>IPC: Ok(formatted) IPC-->>ES: 解析成功 · setOutput(formatted) ES->>CM: 更新输出栏 + 状态栏 "● Valid" else Parse 失败 ENG-->>CMD: Err(Parse { line, col, msg }) CMD-->>IPC: Err(JsonitaError::Parse) IPC-->>ES: setError({ line, col, msg }) ES->>CM: 高亮 line:col · 状态栏 "● Line X, Col Y" ES->>ES: showAiFix = true (出现 AI Fix Tab) end

7错误传播模型

所有 Rust 错误统一映射到单一 JsonitaError enum（8 个变体，完整定义见 13 § 1），经 serde 序列化跨 IPC 边界传到前端，由前端按 UI 分级 渲染。

分级原则（详见 02 § 3.3）：

  • 状态栏（轻）：用户输入边解决，如 Parse ── 不打断
  • Toast（中）：操作失败但应用可继续，如 Http / RateLimit / UnwrapTimeout
  • Modal（重）：必须用户决策才继续，如 AiInvalidJson raw 决定 / secrets fs 写失败

设计原则：Rust 不"产品化"错误（不翻译中文、不加 emoji），UI 层按 kind 决定如何展示给用户。
